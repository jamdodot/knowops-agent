### 关于跳转的实话（这条不改会写出死链）

`Citation` 契约（`schemas.py:191`）只有 `eid / doc_id / title / page_no / section_path / acl_epoch`，**没有 url**；`api/openapi.yaml` 也**没有**"取文档正文"的接口（只有 `/v1/knowledge/answers`、`/v1/fulfillment/tasks*`）。

所以"点击可跳转"必须分层实现，否则前端只能 `fetch('/v1/knowledge/documents/...')` 拿到 404：

- **L1（必做，零后端）**：点击引用 → 右侧抽屉展示 `title / doc_id / 第 N 页 / section_path`，正文里 `<sup>` 角标点击可反查并高亮对应卡片。
- **L2（必做，兼容分支）**：写 `if (c.url)`，有值就在卡片右上角渲染 `↗`，新窗口打开。**后端哪天补了 url，前端不用改代码。**
- **L3（可选，只留形状）**：若要"真的看到原文片段"，需要后端新增 `GET /v1/knowledge/documents/{doc_id}?page=N`（含 ACL 复核）。提示词里要求前端**预留 `renderSourcePreview()` 空实现**，但不许自己造接口。

# 角色

你是 KnowOps 项目的资深前端工程师。KnowOps 是一个**权限感知的 Agentic RAG 系统**（企业知识问答 + 订单工单排障），当前只有一套给内部用的评测控制台。现在要为 **ToC 用户**（普通员工，不懂"检索""召回""假设验证"这些词）新增一套对话式界面，交互参照豆包：进来就能问，答案下面带可点击的知识来源。

# 一、先读事实，不要猜（这些是已验证的现状）

## 1.1 服务拓扑

| 服务 | 端口 | 前端如何访问 | 说明 |
|---|---|---|---|
| 知识域 | `8001` | 同源相对路径 `/v1/...` | 同时用 `StaticFiles` 在 `/` 挂载 `web/`（`app_knowledge.py:338`） |
| 排障域 | `8002` | **绝对地址** `http://${location.hostname}:8002` | 独立进程，已开 `CORSMiddleware`（`app_fulfillment.py:126`） |

- 现有前端是**零构建**的原生 HTML/CSS/JS（`web/index.html` + `styles.css` + `app.js`，共 2451 行），项目**没有 package.json、没有 node 构建链**。
- 现有 `web/` 有 4 个视图：知识问答 / 订单排障 / 权限对比 / 评测看板，是内部评测台。**本次不动它。**

## 1.2 两个入口的接口契约

**知识检索** → `POST /v1/knowledge/answers`（同源）

```json
{ "query": "string(1..2000)", "subject_ctx": {...}, "session_id": "s_xxx", "turn_seq": 1 }
```

响应是**一条 SSE 流**，首 token 目标 < 1.5s。

**工单排障** → `POST http://{host}:8002/v1/fulfillment/tasks`（跨域）

```json
{ "symptom": "string(1..2000)", "subject_ctx": {...}, "session_id": "s_xxx" }
```

响应 `201` + SSE 流。命中审批或需补充信息时发 `input_required` 并**正常关闭流**，任务转 `paused`；恢复走 `POST /v1/fulfillment/tasks/{task_id}/resume`（必须重传 `subject_ctx`）。

**`subject_ctx` 必填字段**（`user_id / account_status / dept_paths / roles / subject_epoch`）。本期固定一个员工身份即可，收敛到 `getSubject()` 单函数，**不要做登录页**。

## 1.3 SSE 事件契约（顺序由后端强制，违反会抛 ContractViolation）

知识域事件序列：

```
meta → citation → delta* → (done | input_required | error)
```

| 事件 | 何时 | 关键字段 | UI 必须怎么反应 |
|---|---|---|---|
| `meta` | **永远第一帧** | `trace_id / contract_version / config_version / degraded[]` | 不渲染内容；`degraded` 非空时在顶部挂一条降级提示 |
| `citation` | **必定早于正文** | `citations[]` | 先渲染"已找到 N 条依据"骨架，编号此刻就要定下来 |
| `delta` | 流式正文 | `text`、`eids[]` | 追加渲染；`text` 里的引用是**占位符 `{e_3}`** |
| `done` | 正常结束，**有且仅有一个** | `finish_reason`、`usage`、`citations?`、`task_id?`、`degraded?` | 按 `finish_reason` 决定结算样式 |
| `input_required` | 暂停（**不是错误**） | `task_id`、`kind`、`approval?`、`question?`、`schema?` | 渲染审批卡 / 追问表单，给"继续"入口 |
| `error` | 失败 | `trace_id`、`code`、`message` | 红色错误块 + trace_id 可复制 |

排障域额外事件：`progress`（`node/step/note`）、`evidence`（`hypothesis_id/verdict/summary`）、`action_proposal`（`approval`）。

**四条不能违反的渲染铁律：**

1. **引用编号由前端生成，不是后端给的。** 正文里是 `{e_3}` 这种占位符，必须按 `citation` 帧的到达顺序映射成 `1、2、3…`，并渲染成 `<sup>3</sup>`。**绝不允许直接把 `{e_3}` 原样显示给用户。**
2. **`abstained` 是设计内行为，不是错误。** 渲染成中性的"没有找到足够依据"，配一个"换个问法 / 转人工"的建议，**不要用红色报错样式**。同理 `escalated` / `degraded` 也各有样式。
3. **`done.degraded` 非空必须显式提示**（例如"本次排序服务超时，结果可能不够精确"）。后端纪律是"禁止静默降级"，前端不许把这批标记丢掉。
4. **流断了 ≠ 失败。** `input_required` 之后是 `paused`，UI 要给"继续"按钮（调 resume），不能显示成错误。

## 1.4 引用对象长什么样

```js
{ eid: "e_3", doc_id: "doc_881", title: "《仓配作业规范》",
  page_no: 12, section_path: "第3章 > 3.2 签收异常", acl_epoch: 7 }
```

- **没有 `url` 字段**（见第一节"关于跳转的实话"）。
- `acl_epoch` 是"引用时刻的权限版本"：若与页面上拿到的当前 epoch 不一致，卡片要**置灰并标注"原文已失权"**，且不再可点。

垂直居中，从上到下：

1. **品牌语**：一行大字 `有什么可以帮你？`（24px / 500 字重），下面一行 13px 灰字 `查制度、查流程、排故障，答案都带原文出处`。
2. **大输入框**：
   - 最大宽 720px，圆角 20px，白底 + `1px solid #E5E7EB`，聚焦时边框转主色 + `box-shadow: 0 0 0 3px rgba(15,110,86,.12)`。

   - 内部：左上一个"＋"（上传，本期 `disabled` + `title="即将支持"`），右下发送圆钮 36px（空内容时灰、有内容时主色填充）。
   - `Enter` 发送、`Shift+Enter` 换行（IME 组字中不触发，必须判 `isComposing`）。
3. **两个入口**（**这是本次需求的核心，必须显眼**）：并排两张卡片，各 340×96px，圆角 16px，`1px` 边框，hover 时边框转主色 + 轻微上浮 2px：

| 卡片 | 标题 | 副文案 | 图标语义 |
|---|---|---|---|
| 左 | **知识检索** | 问制度、问流程、问规范，回答附原文出处 | 文档 / 书 |

  - 知识检索：`例如：签收异常超过 48 小时该怎么处理？`

## 2.3 对话态

- **用户消息**：右对齐，浅灰气泡（`#F4F5F7`），圆角 18px，最大宽 80%，内边距 `10px 14px`。
- **助手消息**：**左对齐、无气泡**（正文直接铺开在页面上，这是豆包式观感的关键），宽度与主区一致。
- **首 token 之前**：不要放 spinner。渲染一行状态文字 + 三个点的呼吸动画，文案随模式不同：
  - 知识检索：`正在检索…` → 收到 `citation` 后变 `已找到 3 条依据，正在组织答案…`
  - 工单排障：`正在分析现象…`，收到 `progress` 后按 `note` 更新为 `正在核查：库存占用`
- **流式正文**：末尾跟一个 `▍` 光标（1px 宽、主色、1.1s 闪烁），`done` 后消失。
- **正文渲染**：只支持极简 markdown——`**粗体**`、空行分段、单换行 `<br>`、`- ` 列表。**不许上 markdown 库**，也不许用 `innerHTML` 拼接未转义内容（必须复用现有 `esc()` 思路）。
- **底部操作条**（`done` 后出现）：`复制` · `重新生成` · 反馈 👍/👎（本期只做视觉，点击写 `localStorage` 即可）。
- **结算提示**按 `finish_reason` 分四种样式：`answered`（无额外提示）、`abstained`（中性灰条 + 换问法建议）、`escalated`（蓝条 + "已为你转人工，工单号 xxx"）、`degraded`（浅黄条 + 降级项说明）。

## 2.4 引用区（本次重点，必须做到"能点、能看懂、不骗人"）

位置：**答案正文下方**，与正文同宽，距正文 20px。

**A. 折叠头部**

```
🔗 引用 3 条                                    [展开 ▾]
```

- 默认**展开**（ToC 用户需要看到"有出处"这件事），超过 5 条时默认折叠。
- 显示 `已引用 2 / 共 3`：正文里真正用到的 `eid` 与总引用数之比，用 `delta.eids` 和正文占位符求并集算。

**B. 引用卡片**（列表，每行一张，高 64px，圆角 12px，hover 底色 `#F7F8FA`）

```
┌────────────────────────────────────────────────────────────┐
│ ①  《仓配作业规范》                              ↘  ↗      │
│     第 12 页 · 第3章 > 3.2 签收异常 · doc_881              │
└────────────────────────────────────────────────────────────┘
```

- 序号徽标 20×20 圆角 6px、主色浅底 + 主色字，**与正文 `<sup>` 里的数字严格一致**。
- 标题最多 1 行省略号；第二行 12px 灰字：`第 N 页 · section_path · doc_id`（`page_no` / `section_path` 缺失时按顺序降级，都没有就只显示 `doc_id`）。
- 卡片右侧两个动作：
  - `↗` **仅在 `c.url` 存在时渲染**，`target="_blank" rel="noopener"`。
  - `↘` 打开引用详情抽屉（始终存在）。
- `acl_epoch` 与当前不一致 → 整卡 `opacity:.45`、`cursor:not-allowed`、徽标替换为 `已失权`，点击弹 toast「该文档权限已变更，引用不可查看」。

**C. 正文角标联动**

- 点正文里的 `<sup>` → 打开抽屉 + 对应卡片加 `.is-focus`（主色左边框 3px）+ `scrollIntoView({block:'nearest'})`。
- 点卡片 → 抽屉打开同时，正文里所有该 `eid` 的角标短暂高亮（1.2s 后恢复）。

**D. 引用详情抽屉（右侧 400px，`transform: translateX(100%)` → `0`，180ms ease-out）**

从内到外：

1. 头部：`引用 ①` + 关闭按钮（`Esc` 也关）。
2. 标题（16px/600）+ 位置行（`第 12 页 · 第3章 > 3.2 签收异常`）。
3. **原文片段区**：调用 `renderSourcePreview(citation)`——
   - 本期该函数返回**占位提示**：`原文预览需要后端提供文档接口，暂不可用`（小字灰，不报错、不空白）。
   - **不许自己 `fetch` 一个契约里不存在的接口**，也不许伪造内容。
4. 底部：`复制引用信息`（写剪贴板：标题 + 页 + 文档 ID）+ `打开原文 ↗`（仅 `c.url` 存在时显示）。
5. 关闭态：点遮罩、点关闭、`Esc` 三个入口都要有。

## 2.5 工单排障模式的额外 UI

- **不要复用引用区**（排障域没有 `citation` 事件）。改为"**排查时间线**"：每个 `progress` 追加一行 `✓ 正在核查：库存占用`，进行中的带呼吸点；`evidence` 渲染成结论标签（`成立` 绿 / `不成立` 灰 / `不确定` 黄）+ 一句 `summary`。
- `action_proposal` → **审批卡**：动作名（`retry_push_carrier` 这类要翻成人话，如"重新推送承运商"）、`risk_level` 用色标（高=红/中=黄/低=绿）、两个按钮 `批准` / `拒绝`（拒绝必填原因，回灌给 Agent）。
- 点批准/拒绝 → 调 `POST /v1/fulfillment/tasks/{task_id}/resume`，body 带 `subject_ctx` + `approval: {approval_id, decision, comment}`，然后**接一条新的 SSE 流继续渲染**（不是重开新会话）。
- `input_required(kind=clarification)` → 按 `schema` 渲染简单表单（string → input，enum → select），提交同样走 resume。

## 2.6 会话管理

- `session_id` 用 `crypto.randomUUID()` 生成，存 `sessionStorage`；`turn_seq` 每轮 +1。
- 左侧历史列表存 `localStorage`（标题取首条用户消息前 20 字），点击切换 `session_id` 并**只恢复本地缓存的问答**（后端是无状态 + task 查询，别假装有服务端历史）。
- 顶部必须有 `服务状态` 指示灯：轮询 `/healthz` 与 `:8002/healthz`，任一不通就在输入框上方挂一条黄色提示，并把该入口卡片置灰。

# 三、挂载方式（有一个顺序坑，必须注意）

在 `agent-service/api/app_knowledge.py` 里，**`/app` 必须注册在 `"/"` 那个 mount 之前**，否则根 mount 会把 `/app` 吞掉：

```python
app.mount("/app", StaticFiles(directory=str(WEB_ROOT / "app"), html=True), name="toc")
app.mount("/", StaticFiles(directory=str(WEB_ROOT), html=True), name="web")   # 原有那一行，位置不变
```

- 静态资源全部用**相对路径**引用（`./app.css`、`./app.js`），保证挂在子路径下也能加载。
- 不要改 `/v1/*` 任何路由。

# 四、验收清单（逐条自查，不要跳）

| # | 检查项 | 通过标准 |
|---|---|---|
| 1 | 首屏 2 秒内可用 | 打开 `/app` 立刻看到品牌语 + 输入框 + 两个入口，无白屏、无布局抖动 |
| 2 | 双入口可切换 | 点卡片切模式，placeholder 与选中态同步变化，焦点进输入框 |
| 3 | 流式渲染正确 | 正文逐字出现，`{e_3}` 全部变成上标数字，**页面上看不到任何 `{e_...}` 原文** |
| 4 | 引用数量对得上 | 卡片数 = `citation` 帧里的 `citations.length`；序号与正文角标一致 |
| 5 | 角标双向联动 | 点角标→卡片高亮+抽屉开；点卡片→正文角标闪亮 |
| 6 | 抽屉可关 | 点遮罩/关闭/`Esc` 都能关，动画不卡顿 |
| 7 | 无 url 时不出现死链 | 契约里没有 `url` 时，`↗` 按钮**完全不渲染**；点卡片仍是抽屉，不跳 404 |
| 8 | 失权引用有提示 | 把 `acl_epoch` 手动改小，卡片置灰、标注"已失权"、不可点 |
| 9 | `abstained` 不报错 | 走 `finish_reason=abstained` 分支时是灰条 + 建议，不是红色错误块 |
| 10 | 降级不吞 | `done.degraded=["rerank"]` 时页面有明确提示文案 |
| 11 | 暂停态可续 | 收到 `input_required` 后出现"继续"入口，resume 后同一处继续渲染 |
