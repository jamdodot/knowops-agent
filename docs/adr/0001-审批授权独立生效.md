# ADR-0001 审批授权独立于组织架构生效

- **状态**：已接受
- **日期**：2026-11-02
- **影响范围**：权限求值、审批流、组织变更事件、审计报表、`kb_approval` 表结构

---

## 背景

用户可见文档 = 公开 ∪ 部门 ∪ 角色 ∪ 点对点 ∪ 审批，取并集。

当同一份文档同时被「部门授权」与「审批授权」覆盖时，撤销部门授权后用户是否仍可见？
并集语义在技术上给出"是"。但如果审批的动机是"因为你在 D10 才批给你的"，
调岗之后是否应当失效，需要一个明确规则，否则线上必然出现业务方与技术方的争论。

---

## 决策

**采用方案 A：审批授权一旦通过，在有效期内独立于组织架构变更。**

求值条件只有一条，不含任何对当前部门的判断：

```
审批授权有效 ⇔ kb_approval.status = 'approved'
             AND kb_approval.expire_at > now()
             AND kb_approval.action ⊇ 请求的动作
```

---

## 关键：三个"失效"维度必须分开

这一条比决策本身更重要，混淆任意两个都会出事：

| 维度 | 触发事件 | 是否使审批授权失效 | 求值位置 |
|---|---|---|---|
| **授权失效** | 审批到期、审批人主动撤销 | 是 | 审批条件内部 |
| **主体失效** | 离职、账号停用、账号锁定 | **是，一票否决** | SubjectContext 解析，**先于所有授权求值** |
| **组织变更** | 调岗、部门调整、角色变更 | **否**（本决策） | 不参与审批求值 |

**主体失效必须一票否决。** "审批独立"指的是独立于**组织架构**，不是独立于**人是否还在职**。
离职员工因审批未到期而仍能访问，是这类设计最容易漏掉的严重漏洞。

实现上：`SubjectContext` 解析时先校验账号状态，`status != 'active'` 直接返回空授权集，
后续任何审批条件都不会被求值。

---

## 后果

### 正面

- 求值无回溯依赖，可在检索那一条 SQL 内完成，不破坏核心性质
- 语义可解释：审批是契约，契约期内有效
- 规避了"绑定哪个部门"的歧义——矩阵组织、兼职、双线汇报下根本无法定义

### 负面

- 调岗后仍可访问旧部门文档，直到审批到期，存在合规敞口
- 审批容易"长期化"，变成变相永久授权

### 缓解措施（必须全部实现，缺一即视为决策未落地）

| # | 措施 | 目的 |
|---|---|---|
| 1 | `kb_approval.granted_context` 存申请时的部门/角色快照，**仅审计用，不参与求值** | 事后可追溯当时凭什么批 |
| 2 | 调岗事件触发「受影响审批复核」：列出该用户当前持有的审批授权，推给文档 owner 决定是否提前撤销 | 把合规判断交还给业务方 |
| 3 | 单条审批有效期上限 90 天，到期需重新申请 | 防止长期化 |
| 4 | 单用户有效审批持有量软上限 50 条，超过触发人工复核 | 同时保证 `approval_doc_ids` 小集合假设成立；超过阈值的用户降级为"强一致 join"模式 |
| 5 | 月度审计报表：输出「申请人已不在授权部门、但审批仍有效」清单 | 主动暴露敞口 |
| 6 | 通过审批命中的访问，审计日志记 `grant_source='approval:AP-xxx'` | 可回溯到具体审批单 |

第 4 条的降级路径值得单独说明：本设计的前提是审批授权是"几十条以内的小集合"。
若某用户持有量突破阈值，`= ANY($approval_doc_ids)` 会退化为大数组。
此时该用户改走"直接 join `kb_approval` 表"的强一致查询，牺牲延迟换取正确性——
**这是唯一允许偏离"小集合"假设的出口，且必须显式记录。**

## 备选方案与否决理由

### 方案 B：审批绑定申请时部门，部门变化则失效

| | 说明 |
|---|---|
| 优点 | 权限更收敛，符合"因岗授权"的直觉 |
| 否决原因 1 | 矩阵组织/兼职场景下"绑定哪个部门"无法定义，规则写不出来 |
| 否决原因 2 | 每次求值需回查审批上下文，一条 SQL 做不完，破坏鉴权与检索同语句 |
| 否决原因 3 | 被动调岗导致已批准权限突然消失，用户体验与合规解释都站不住 |

### 方案 C：每次访问都弹确认

否决：把审批的运营成本转嫁到每次问答上，与"降低查找成本"的产品目标冲突。

---

## 重审触发条件

出现以下任一情况，应重新评估本决策：

1. 合规方明确要求"审批必须随人所在部门失效"
2. 审批授权平均持有量超过 30 条/人（说明审批在泛滥）
3. 发生因调岗后仍可访问而导致的越权事件
4. 组织架构调整为频繁变动型（季度级重组），敞口随时间扩大
