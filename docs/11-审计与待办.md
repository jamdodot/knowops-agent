## 2. P0：已修复的 12 处

### 2.1 `allowed_doc_ids` 与"不展开文档清单"直接冲突（最严重）

**位置**：`01` §5.2/§5.4、`02` §2、`03` §5.2/§5.3

`05` 用整节论证"不把权限展开成文档 id 清单，否则 1500 万条缓存 + 失效风暴"，
但另外三份文档的接口签名写的是 `Java → Python: {query, subject, allowed_doc_ids, ...}`。

**这是自相矛盾的**：如果 Java 已经把清单算出来了，检索侧的条件求值就没有意义，
整个"权限是检索语句的一部分"的论点被自己的接口推翻。面试官只要问一句"你传的是清单还是条件"就崩。

**修法**：接口改为透传 `subject_ctx`（`dept_paths / roles / groups / approval_doc_ids / acl_epoch`），
鉴权条件由 Python 拼进 SQL。三个落点全部改口径。

### 2.2 检索 SQL `JOIN kb_document`，但该表在 MySQL

**位置**：`05` §3

跨库 JOIN 物理上不存在。**修法**：PG 增加 `kb_doc_mirror`（文档级快照，只存元数据不存正文），
SQL join 它；并解释"为什么必须有一张 PG 本地副本"。

### 2.3 "强一致读 = 直接 join MySQL 授权表"

**位置**：`06` §4、`05` §6.4

同上，PG 里的查询 join 不到 MySQL，除非上 FDW（下推不可控）。
**修法**：改成**收权同步写、放权异步写**——用写顺序保证方向性，而不是用读操作跨库。
这条改完反而更强：它把"宁可失权不可越权"从口号落成了可执行顺序。

### 2.4 `GIN(acl_jsonb jsonb_path_ops)` 不支持 `?` / `?|`

**位置**：`06` §2 vs `05` §3 SQL

`jsonb_path_ops` 只支持 `@>`。用 `?|` 判数组元素必须用默认 `jsonb_ops`，否则建完索引查询直接报
"operator does not exist"。**修法**：索引改 `jsonb_ops`，并在要点表里写明原因；
另补一条 `text[] + &&` 的优化路径与"当前不做"的理由（瓶颈在 HNSW 不在过滤）。

### 2.5 PyMuPDF 许可证两处写法相反

**位置**：`02` §1 写"宽松"，`09` §8 写 AGPL-3.0

**修法**：`02` 拆行并标 AGPL-3.0。这条对作品集无碍，但对企业落地是硬门槛，
两处说法不一致会让人怀疑"到底查没查过"。

### 2.6 judge 模型写成 `gpt-4o-mini`

**位置**：`03` §4.1

与 ADR-0003（judge 走硅基流动、必须与生成异源）矛盾，且是境外模型。
**修法**：改 `siliconflow/qwen3-235b`，`grade_model` 改 `siliconflow/qwen3-flash`，与 `config/models.yaml` 的角色命名对齐。

### 2.7 入库流程写"嵌入 dense+sparse"

**位置**：`01` §5.1

与 `02` §3"不做单模型双输出"矛盾。**修法**：改"只取 dense，稀疏一路由 pg_search 的 BM25 承担"。

### 2.8 权限出口计数：7 / 8 打架

**位置**：`05` §5 标题写"七个"，表格 8 行；`07` §3.3 写"05 列了前七个，这里补第八个"

**修法**：统一为八个，`07` 改为"05 完整列了八个，第八条就是本节场景"。

### 2.9 传播链路写"两条"，表格 3 行

**位置**：`05` §6.3

点对点共享补进来后没改标题。**修法**：改三条。

### 2.10 越权集规模：80 / 100 两个数

**位置**：`03` §3.1 写 100，`03` §3.4 与 `05` §8 写 80（4 类角色 × 20 份），`04` §4 写 100

**修法**：统一 80。**理由**：4×20 是能推导出来的，100 是拍的——报告里出现两个数最容易被追问"到底多少条"。

### 2.11 容器数：同文档内 7 个 / 1 个

**位置**：`06` §1 写"核心链路 7 个"，`06` §5 写"M0~M2 收敛为 1 个 PG 容器"

**修法**：`06` §1 注明"7 个是完整形态，1 个是 M0~M2 实际形态"，并在 `02` §8 加同样说明。

### 2.12 `parse_report` 字段落后于 `09` 与 `parse.yaml`

**位置**：`06` §2

`09` 与 `parse.yaml` 都要求 `engine / route / deploy / header_footer_leak`，`06` 里只有 5 个统计字段。
**修法**：补全。归因要能区分"本地慢"和"云端排队"，就必须有 `deploy`。

## 5. 一句话总结

> 这次审计真正修掉的不是错别字，而是**"我讲的机制"和"我画的接口"不一致**。
> 最典型的一处是 `allowed_doc_ids`：文档正文在论证"不展开清单"，接口签名却在展开清单。
> 这种矛盾自己看不出来，但只要有人顺着接口问一句，整套论证就塌了。

## 7. 第三轮：补 M1 前置三项

> 触发原因：第二轮把"文档 + 简历"对齐了，但第 3 节的 8 个缺口仍未动。
> 其中第 1、2、7 条是**其他模块的前置依赖**（评测要 `config_id`、双服务要契约、归因要 span 结构），
> 不补就只能靠嘴说。本轮把这三条补成独立文档 + 可执行配置。

### 7.1 本轮产出

| 产出 | 对应缺口 | 核心结论 |
|---|---|---|
| `docs/12-Prompt治理.md` | #1 | prompt 是有一等版本、指纹、灰度、回滚的资产；**三个 hash 分工不同**（模板 / 渲染 / 集合）；回滚单位是 `config_version` 而不是单个文件 |
| `config/prompts.yaml` | #1 | 策略可执行化：门禁阈值、三档灰度、自动回滚、semver 规则、lock 策略 |
| `docs/13-服务间契约.md` | #2 | 三条通道（两条 REST+SSE、一条 A2A）；`subject_ctx` 是唯一权限载体，**`extra="forbid"` 让 `allowed_doc_ids` 加不回来** |
| `api/openapi.yaml` | #2 | 唯一真相源：7 个路径、20 个 schema、SSE 事件用 `x-sse-event-types` 描述，双端 codegen |
| `docs/14-Span规范.md` | #7 | 命名 `{domain}.{layer}.{op}`；维度进属性不进名字；**E1~E10 / F1~F7 逐条钉到具体字段** |

### 7.2 本轮新发现并修掉的 3 处口径问题

补新文档的过程等于又做了一次交叉审计，发现三处：

| # | 问题 | 修法 |
|---|---|---|
| 1 | `subject_ctx.groups` 只在 SQL 里存在，`05` §2.2 与 `06` 的缓存行都没它 | 两处补齐，`13` §3.1 定为必传可空 |
| 2 | `acl_epoch` 一词三义（文档级 / 主体级 / `chat_turn` 冗余） | `13` §3.3 定最终口径：文档级进引用、主体级进请求体、`chat_turn` 那个是命名债 |
| 3 | 排障域 HITL 中断后**没有恢复入口**：审批等几分钟，网关超时就掐断，checkpointer 停在 `human_approve` 却没人唤醒 | `13` §2 定为有状态 Task + `input_required` + `resume`，**断流 ≠ 任务失败** |

第 3 条是这轮真正的收获：它不是"文档没写全"，而是**原设计在 HTTP 边界上跑不通**。
`01` §7 画了 `human_approve` 节点、`07` §4 说了 `interrupt` + `Command(resume)`，
但谁把审批结论送回去、连接怎么不被超时掐掉，三份文档都没写。补契约时才暴露出来。
